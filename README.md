# SkillPath — планирование и трекинг развития IT-карьеры

SkillPath — веб-сервис для студентов и начинающих специалистов: помогает выбрать направление в IT, честно оценить свои навыки, получить личный roadmap и план обучения и отслеживать прогресс. Работает на компьютере и в мобильном браузере, есть светлая и тёмная темы.

**Стек:** HTML / CSS / JavaScript без сборщиков + Vue 3 и Vue Router (CDN) на клиенте; REST API на FastAPI и реляционная СУБД PostgreSQL на сервере.

## Возможности

| Экран | Маршрут | Доступ |
|---|---|---|
| Лендинг и онбординг: шаги работы, преимущества, отзывы | `#/` | открыт |
| Вход и регистрация | `#/auth` | открыт |
| Опрос по интересам | `#/survey` | после входа |
| 2–3 рекомендованных направления с примерами задач | `#/result` | после входа |
| Сравнение всех направлений | `#/compare` | открыт |
| Оценка навыков (чек-лист) | `#/skills` | после входа |
| Roadmap: разделы и темы с процентом изучения, готовность к junior | `#/roadmap` | после входа |
| Карьерный план с выбором темпа (14 / 30 / 60 дней) | `#/plan` | после входа |
| Трекинг прогресса и рекомендации | `#/progress` | после входа |
| Личный кабинет: сводка, данные профиля, история обучения | `#/profile` | после входа |
| База знаний: профессии, технологии, навыки | `#/knowledge` | открыт |
| Контакты / поддержка: FAQ и обратная связь | `#/support` | открыт |

Как это работает:
- **Рекомендации** строятся по правилам из ответов опроса, без внешних сервисов и ИИ.
- **Roadmap** — вертикальный timeline: раздел = навык направления, внутри темы. Проценты тем и разделов считаются по отметкам заданий в карьерном плане.
- **План** учитывает уровень навыков (освоенное в план не попадает) и выбранный темп.
- **Данные пользователя** сохраняются автоматически в PostgreSQL и доступны с любого устройства после входа.
- **Тема** переключается кнопкой ☾/☀ в верхнем меню (по умолчанию светлая), выбор запоминается.

## Архитектура

```
Браузер (Vue 3, статический сайт) ──REST/JSON──▶ API (FastAPI, папка backend/) ──SQL──▶ PostgreSQL
```

Браузер не подключается к PostgreSQL напрямую: строка подключения содержит пароль, а в статическом сайте её увидел бы любой посетитель. Поэтому данные принимает API и сохраняет их в БД.

### Структура проекта

```
index.html            точка входа (подключение скриптов и стилей)
js/                   app.js (маршруты, меню, тема), api.js (клиент API), auth.js (аккаунт и автосохранение),
                      store.js (состояние), directions.js (справочник направлений и навыков),
                      recommendations.js (логика рекомендаций), utils.js

                      Roadmap, RoadmapTimeline, Plan, Progress, Profile, Knowledge, Support)
css/                  styles.css (основные стили), landing.css (лендинг), dark.css (тёмная тема)
assets/               логотип и иллюстрации
backend/              main.py (FastAPI), schema.sql (схема БД), requirements.txt, .env.example
render.yaml           конфигурация хостинга API на Render
docker-compose.yml    локальный PostgreSQL для разработки
```

### REST API

| Метод | Путь | Доступ | Назначение |
|---|---|---|---|
| GET | `/health` | открыт | проверка API и подключения к БД |
| POST | `/api/auth/register` | открыт | регистрация (email, пароль от 8 символов, имя) |
| POST | `/api/auth/login` | открыт | вход, возвращает токен сессии |
| POST | `/api/auth/logout` | токен | выход (сессия удаляется) |
| GET | `/api/me` | токен | данные аккаунта |
| GET / PUT | `/api/me/state` | токен | данные пользователя: опрос, навыки, план, отметки заданий, история |
| DELETE | `/api/me` | токен | удаление аккаунта и всех данных |
| POST | `/api/feedback` | открыт | обратная связь (если пользователь вошёл, привязывается к аккаунту) |

Токен передаётся заголовком `Authorization: Bearer <токен>`. Интерактивная документация API: `/docs`.

### База данных

Схема: [backend/schema.sql](backend/schema.sql). Таблицы `users`, `sessions`, `user_state`, `feedback` создаются автоматически при старте API.

### Аккаунты и безопасность

- Без входа доступны главная, «Направления», «База знаний» и «Поддержка». Опрос, roadmap, план, прогресс и личный кабинет требуют аккаунт.
- Пароль хранится только как хеш PBKDF2-SHA256 (600 000 итераций, случайная соль). В БД лежит SHA-256 от токена сессии, а не сам токен. Сессия действует 30 дней.
- Вход ограничен по числу попыток (8 за 10 минут на пару IP + email), ответ при неверном логине или пароле одинаковый. Регистраций с одного IP — не больше `REGISTER_LIMIT_PER_HOUR` в час (по умолчанию 20).
- В браузере хранятся только токен сессии и выбранная тема; данные пользователя живут в PostgreSQL.
- Для production обязательно: HTTPS и список `ALLOWED_ORIGINS` в `backend/.env`.

## Запуск локально

Не открывайте [index.html](index.html) двойным кликом (`file://`): браузер блокирует запросы к API. Запускайте через HTTP-сервер. Нужны три вещи: PostgreSQL, API и статический сервер для фронтенда.

### 1) PostgreSQL

Вариант с Docker (из корня проекта):

```
docker compose up -d
```

Будет поднят PostgreSQL 16 с пользователем, паролем и базой `skillpath` на `127.0.0.1:5432`.

Без Docker подойдёт любой установленный PostgreSQL: создайте базу и пользователя и укажите их в `DATABASE_URL` (следующий шаг).

### 2) API

В PowerShell, в корне проекта:

```
python -m venv .venv
.venv\Scripts\activate
pip install -r backend/requirements.txt
copy backend\.env.example backend\.env
```

Откройте `backend/.env` и при необходимости поправьте значения:

| Переменная | Назначение |
|---|---|
| `DATABASE_URL` | строка подключения к PostgreSQL (обязательна) |
| `ALLOWED_ORIGINS` | адреса сайта, которым разрешены запросы к API (через запятую) |
| `REGISTER_LIMIT_PER_HOUR` | лимит регистраций в час с одного IP |

Запуск:

```
uvicorn backend.main:app --host 127.0.0.1 --port 8081
```

Проверка: `http://127.0.0.1:8081/health` → `{"status":"ok"}`.

### 3) Фронтенд

В другом окне PowerShell:

```
python -m http.server 5173
```

Откройте `http://127.0.0.1:5173`. Локально сайт обращается к API на `http://127.0.0.1:8081` (`LOCAL_API_URL` в [js/api.js](js/api.js)); адрес можно переопределить без правки файла:

```js
localStorage.setItem('skillpath_api_base_url', 'https://api.example.com')
```

После обновления файлов сайта нажмите Ctrl+F5: скрипты и стили подключены с номером версии (`?v=…`) в `index.html`, при своих правках увеличивайте его.

## Развёртывание

Сайт состоит из двух частей, и **обе нужно разместить**: без API на размещённом сайте не заработают вход и регистрация.

1. **База данных PostgreSQL.** Подойдёт любой управляемый Postgres, например [Neon](https://neon.tech) или ваш проект Supabase (как обычный Postgres). Нужна строка подключения (`DATABASE_URL`). Для Supabase берите строку из раздела Connect → **Session pooler**. Таблицы создаются автоматически при первом запуске API, доступ через публичный REST Supabase закрывается (RLS включён в [схеме](backend/schema.sql)).
2. **API** — папка [backend/](backend/) на любом Python-хостинге. Для Render в репозитории есть [render.yaml](render.yaml): New → Blueprint → выберите репозиторий и задайте переменные окружения `DATABASE_URL` и `ALLOWED_ORIGINS` (адрес сайта на Vercel, без слеша в конце). Проверка после запуска: `https://<адрес-api>/health` → `{"status":"ok"}`.
3. **Сайт** — статические файлы из корня репозитория (Vercel, GitHub Pages). Конфигурация Vercel: [vercel.json](vercel.json), серверная часть исключена из выкладки через [.vercelignore](.vercelignore). Впишите https-адрес API в `PRODUCTION_API_URL` в [js/api.js](js/api.js) и отправьте изменения в GitHub: Vercel обновит сайт автоматически.

Бесплатные тарифы хостингов могут «засыпать» без запросов: первый вход после паузы иногда занимает около минуты.
