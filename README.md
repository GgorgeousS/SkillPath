# SkillPath — MVP профориентации в IT

SkillPath — учебный MVP мини‑сервиса, который помогает подобрать IT‑направление по выбранным интересам/темам и оценить навыки под выбранную роль.

Стек: HTML/CSS/JS без сборщиков + Vue 3 (CDN) + Supabase (сохранение отправок в БД). Подходит для размещения на GitHub Pages.

Это первый релиз (v1): реализован базовый сценарий. Дальше планируется разработка дополнительных страниц и расширение функционала.

## Как запустить проект локально

Важно: не открывайте [index.html](index.html) двойным кликом как файл (`file://...`). В таком режиме браузер часто блокирует `fetch` (ошибки вида `Failed to fetch` / CORS), поэтому интеграции и роутинг могут работать некорректно.

Запускайте проект как обычный сайт через локальный HTTP‑сервер.

### 1) Запуск фронтенда (статический сайт)

Откройте PowerShell в корне проекта (там, где [index.html](index.html)) и выполните:

`python -m http.server 5173`

После этого откройте в браузере:

`http://127.0.0.1:5173`

### 2) Запуск CRM backend (FastAPI)

Во втором окне PowerShell (тоже в корне проекта):

`$env:CRM_API_KEY="<ВАШ_СЕКРЕТ>"`

`uvicorn crm_api.main:app --host 127.0.0.1 --port 8081`

Проверка:

`http://127.0.0.1:8081/health`

Если фронтенд и backend запущены, отправка формы на экране навыков должна уходить на `http://127.0.0.1:8081/api/leads`.

## Этап 4 — Интеграции (CRM API)

В проект добавлен вариант C (API интеграция): при отправке формы на экране навыков данные автоматически отправляются в CRM через HTTP API.

### CRM backend

В репозитории есть учебный CRM backend: папка `crm_api/` (FastAPI + SQLite).

1) Установить зависимости и запустить API:

`pip install -r crm_api/requirements.txt`

Задать ключ доступа (пример для PowerShell):

`$env:CRM_API_KEY="my-secret-key"`

> Важно: `CRM_API_KEY` — это ключ для **вашего** backend-прокси (`crm_api/`), а не ключ Bitrix24.

`uvicorn crm_api.main:app --host 127.0.0.1 --port 8081`

#### Откуда взять CRM_API_KEY (очень подробно)

`CRM_API_KEY` — это **не ключ Bitrix24**. Это пароль/секрет для **вашего** backend-прокси (FastAPI) из [crm_api/main.py](crm_api/main.py), чтобы посторонние не могли отправлять заявки в ваш API.

То есть “взять” его негде — вы его **создаёте сами**.

1) Сгенерировать ключ (любой длинный случайный)

Вариант A (Python):

`python -c "import secrets; print(secrets.token_urlsafe(32))"`

Вариант B (просто придумать строку):

- длина 20+ символов
- без пробелов

2) Указать ключ на стороне backend

Запуск в текущем окне PowerShell (ключ действует только пока окно открыто):

`$env:CRM_API_KEY="<ВАШ_СЕКРЕТ>"`

`uvicorn crm_api.main:app --host 127.0.0.1 --port 8080`

Важно: если `CRM_API_KEY` **не задан**, backend работает в dev-режиме и **не требует ключ**. Но фронтенд по умолчанию всё равно просит ключ (для дисциплины/production-подобного режима).

3) Указать тот же ключ на стороне фронтенда (2 способа)

Способ 1 (рекомендуется для учебного проекта): через `localStorage`, без изменения файлов

- Откройте страницу SkillPath в браузере
- F12 → вкладка Console
- Выполните команды и обновите страницу:

`localStorage.setItem('skillpath_crm_base_url', 'http://127.0.0.1:8080')`

`localStorage.setItem('skillpath_crm_api_key', '<ВАШ_СЕКРЕТ>')`

Способ 2: вписать прямо в код (только если не страшно “светить” ключ)

- Откройте [js/crm.js](js/crm.js)
- Вверху файла замените:
	- `CRM_API_BASE_URL` на адрес вашего backend
	- `CRM_API_KEY` на ваш ключ

Почему это опаснее: сайт статический, любой посетитель сможет посмотреть этот ключ в исходниках.

2) Проверка:

`GET http://127.0.0.1:8081/health`

### Bitrix24 (создание Contact)

Backend умеет (опционально) отправлять данные формы в Bitrix24 как **Contact** через входящий вебхук.

1) Где взять “ключ” в Bitrix24

В Bitrix24 “ключ” обычно выглядит не как отдельная строка, а как **секрет в URL вебхука**.

Обычно путь такой (названия могут слегка отличаться в разных тарифах/интерфейсах):

- Раздел для разработчиков / интеграций (например, “Разработчикам”, “Приложения”, “Вебхуки”)
- Создать **входящий вебхук** (Inbound webhook)
- Дать права на **CRM**

После создания Bitrix выдаст URL вида:

`https://<ваш_портал>.bitrix24.<tld>/rest/<user_id>/<webhook_code>`

Это и есть секрет. Его нельзя хранить на фронтенде (GitHub Pages), поэтому он задаётся только на сервере.

Подсказка по навигации (может отличаться по тарифу/интерфейсу):

- Левая панель → **Приложения** → **Разработчикам** → **Вебхуки** → **Входящий вебхук**
- или: **Настройки** (шестерёнка) → раздел интеграций/разработчика → **Вебхуки**

2) Настройка переменных окружения backend

Задайте `BITRIX_WEBHOOK_URL` (пример для PowerShell):

`$env:BITRIX_WEBHOOK_URL="https://<ваш_портал>.bitrix24.ru/rest/<user_id>/<webhook_code>"`

Опционально: назначать ответственного сразу при создании контакта:

`$env:BITRIX_ASSIGNED_BY_ID="123"`

Где взять `ASSIGNED_BY_ID` (ID пользователя в Bitrix24):

- Откройте профиль нужного сотрудника (например, “Катя Мурашко”) в Bitrix24.
- В адресной строке обычно есть ID, например `.../company/personal/user/123/` → значит `ASSIGNED_BY_ID=123`.

Если ID в интерфейсе не видно, можно узнать через REST (см. ниже `user.get`).

3) UF_* поля

По умолчанию backend пишет в поля:

- `UF_PERSONA_TYPE`, `UF_INTERESTS`, `UF_SKILLS`, `UF_RECOMMENDED_DIRECTIONS`, `UF_ASSESSMENT_RESULT`, `UF_SOURCE`, `UF_CREATED_AT`

Где посмотреть коды UF_* в интерфейсе Bitrix24:

- CRM → **Настройки** → **Настройки CRM** → **Пользовательские поля** → **Контакты**

Там у каждого поля есть “Код” (это и есть `UF_...`). Эти коды должны совпасть с тем, что вы передаёте.

Если в вашем Bitrix коды пользовательских полей другие, их можно переопределить через env:

- `BITRIX_UF_PERSONA_TYPE`, `BITRIX_UF_INTERESTS`, `BITRIX_UF_SKILLS`, `BITRIX_UF_RECOMMENDED_DIRECTIONS`, `BITRIX_UF_ASSESSMENT_RESULT`, `BITRIX_UF_SOURCE`, `BITRIX_UF_CREATED_AT`

4) Быстро “посмотреть всё через API” (удобно для сверки кодов)

Если у вас уже есть `BITRIX_WEBHOOK_URL`, то прямо в браузере можно вызвать методы:

- Список полей контакта (включая UF_*):
	`GET <BITRIX_WEBHOOK_URL>/crm.contact.fields.json`

- Список пользователей (чтобы найти ID “Катя Мурашко”):
	`GET <BITRIX_WEBHOOK_URL>/user.get.json`

В ответе будет JSON — там можно увидеть ID и реальные коды полей.

### Настройка фронтенда

В `js/crm.js` нужно указать:

- `CRM_API_BASE_URL` (например, `http://127.0.0.1:8081`)
- `CRM_API_KEY` (тот же, что в переменной окружения `CRM_API_KEY` для backend)

Опционально (чтобы не хранить ключ в репозитории) можно задать значения через `localStorage`:

- `skillpath_crm_base_url`
- `skillpath_crm_api_key`
